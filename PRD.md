# PRD: Figma Variables to Tailwind Exports

## Purpose

This plugin exports local Figma Variables and Text Styles into two Tailwind-oriented outputs:

1. Tailwind 4 CSS-first files.
2. Tailwind 3 `tailwind.config.js` and `index.css` files.

The plugin reads Figma data in the main plugin context, sends generated artifacts to the UI, and lets the user download each file from the UI.

## Shared Figma Data Source

The plugin reads local Figma data with async Figma APIs:

```ts
const collections = await figma.variables.getLocalVariableCollectionsAsync();
const variables = await figma.variables.getLocalVariablesAsync();
const textStyles = await figma.getLocalTextStylesAsync();
```

Each variable provides:

- `id`: used for alias lookup and metadata.
- `key`: used for deterministic collision suffixes.
- `name`: used to create token paths, CSS custom property names, and Tailwind config keys.
- `resolvedType`: used to route values as color, number, string, or boolean.
- `variableCollectionId`: used to find the collection and default mode.
- `valuesByMode`: used to read the value for light mode or the collection default mode.
- `scopes`: preserved in JSON export metadata.

Each collection provides:

- `id`: links variables to collections.
- `name`: used to identify color collections and sorting.
- `defaultModeId`: fallback mode for token values.
- `modes`: used to find a `Light` mode first, then fall back to default mode.

Names are normalized with `toTokenPath()`, which splits on `/`, trims segments, converts to kebab-case, removes unsupported characters, and drops empty segments.

CSS custom property names are created by category-specific functions:

- `toCssCustomPropertyName()` for colors, producing `--color-*`.
- `toSpacingCssCustomPropertyName()` for spacing, producing `--spacing-*`.
- `toBorderCssCustomPropertyName()` for border/radius values.
- `toSizeCssCustomPropertyName()` for size values.
- `toTypographyCssCustomPropertyName()` for typography values such as `--family-*`, `--text-*`, `--line-height-*`, and `--font-weight-*`.

Values are converted with:

- `makeColorCssValue()` for colors and aliases.
- `makeTextCssValue()` for strings and numeric typography values.
- `makeLineHeightCssValue()` for line-height values.
- `colorToCss()` for Figma RGBA color values.

## Part 1: Tailwind 4 Iteration

### User Goal

Generate Tailwind 4-compatible CSS-first files from Figma Variables and Text Styles.

The current Tailwind 4 downloads are:

- `base.css`
- `color-tokens.css`
- `typography.css`

These are shown in the UI under the Tailwind 4 section and populated from the export payload fields:

```ts
baseCss
colorTokensCss
typographyCss
```

### Output: `base.css`

`base.css` is generated by:

```ts
buildBaseCss(collections, variables, variablesById)
```

This file emits Tailwind 4 `@theme` declarations for non-color base tokens.

Current output shape:

```css
/* Generated 2026-07-29T... */

@theme {
  --spacing-4: 16px;
  --border-radius-sm: 4px;
  --font-weight-bold: 700px;
}
```

### `base.css` Data Flow

1. Iterate every local variable collection.
2. Ignore pure color collections with `!isColorCollection(collection)`.
3. Filter variables in the collection where `getBaseCssCategory(variable)` is not `null`.
4. Determine each variable category:
   - `COLOR`
   - `spacing`
   - `border`
   - `size`
   - `typography`
5. Read the collection default-mode value:

```ts
const modeValue = variable.valuesByMode[collection.defaultModeId];
```

6. Convert the Figma variable name into a CSS custom property name:

```ts
toBaseCssCustomPropertyName(variable, category)
```

7. Convert the Figma value into CSS:
   - Colors use `makeColorCssValue()`.
   - Line heights use `makeLineHeightCssValue()`.
   - Other text/numeric values use `makeTextCssValue()`.
8. Add declarations into deterministic category buckets.
9. Sort numeric buckets by value, then name.
10. Emit all declarations inside `@theme`.

### Output: `color-tokens.css`

`color-tokens.css` is generated by:

```ts
buildColorTokensCss(collections, variables, variablesById)
```

This file emits Tailwind 4 color tokens inside `@theme`.

Current output shape:

```css
/* Generated 2026-07-29T... */

@theme {
  --color-red-100: #fbe8ea;
  --color-yellow-100: #fff3a3;
  --color-button-primary-default: var(--color-red-500);
}
```

### `color-tokens.css` Data Flow

1. Find the first color collection:

```ts
const colorCollection = collections.filter(isColorCollection)[0];
```

2. Find the `Light` mode if present.
3. Fall back to the collection default mode.
4. Filter local variables to color variables in that collection:

```ts
variable.variableCollectionId === colorCollection.id &&
variable.resolvedType === "COLOR"
```

5. Read each variable value from the selected mode:

```ts
const modeValue = variable.valuesByMode[lightMode.modeId];
```

6. Convert the value:
   - Direct Figma RGBA values become hex or modern RGB alpha strings.
   - Aliases become CSS variable references when the target is known.
7. Convert the Figma variable name to a Tailwind 4 color variable:

```ts
toCssCustomPropertyName(variable.name)
```

8. Emit the declaration in `@theme`.

### Tailwind 4 Alias Behavior

Aliases are recognized by:

```ts
isAliasValue(value)
```

When the alias target exists and is a color variable:

```ts
var(--color-target-name)
```

is emitted instead of flattening the resolved color.

### Output: `typography.css`

`typography.css` is generated by:

```ts
buildTypographyCssFromTextStyles(textStyles, variablesById, variables)
```

This file uses Figma local Text Styles and emits Tailwind 4 utility definitions.

Current output shape:

```css
/* Generated 2026-07-29T... */

@utility text-header1 {
    font-size: var(--text-heading-h1);
    line-height: var(--line-height-heading-h1);
    font-weight: var(--font-weight-bold);
}
```

### `typography.css` Data Flow

1. Read local text styles with:

```ts
figma.getLocalTextStylesAsync()
```

2. Filter styles to project text styles where the normalized name starts with `zb` or `zb-*`.
3. Serialize each text style into a JSON-safe record.
4. Resolve font weight from:
   - Runtime `fontWeight`.
   - Font style name, such as `Regular`, `Medium`, `Bold`.
5. Build lookup maps from primitive variables:
   - `getPrimitiveLineHeightVariableMap()`
   - `getPrimitiveFontWeightVariableMap()`
   - `getPrimitiveSizeVariableMap()`
6. For each text style, prefer bound Figma variables when present:

```ts
getBoundVariableCssName(style, "fontSize", variablesById)
getBoundVariableCssName(style, "lineHeight", variablesById)
getBoundVariableCssName(style, "letterSpacing", variablesById)
getBoundVariableCssName(style, "fontWeight", variablesById)
```

7. Fall back to primitive token maps or raw style values.
8. Build a utility class name from the text style name.
9. Emit a Tailwind 4 `@utility` block.

### Tailwind 4 Known Gap

`buildColorTokensCss()` currently scans only the first color collection. The Tailwind 3 config generator was updated to scan all color variables across all collections, but Tailwind 4 color output has not yet received that same iteration.

Recommended next Tailwind 4 iteration:

- Change `buildColorTokensCss()` to scan all local `COLOR` variables.
- Use each variable collection's `Light` mode or default mode.
- Preserve deterministic sorting by collection name and variable name.
- Emit all generated `--color-*` declarations into `@theme`.

## Part 2: Tailwind 3 Iteration

### User Goal

Generate Tailwind 3 files that match the target project format:

- `tailwind.config.js`
- `index.css`

The Tailwind 3 downloads are shown in the UI under the Tailwind 3 section and populated from:

```ts
indexCss
tailwind3Config
```

### Output: `tailwind.config.js`

`tailwind.config.js` is generated by:

```ts
buildTailwind3Config(collections, variables, variablesById)
```

Current output shape:

```js
module.exports = {
  content: ["./src/**/*.{astro,html,js,jsx,ts,tsx,vue}"],
  darkmode: "class",
  theme: {
    fontFamily: {
      sans: [
        "var(--family-noto-sans-sc)",
        "Arial",
        "sans-serif",
      ],
    },
    colors: {
      yellow: {
        100: "var(--color-yellow-100)",
        "500-opacity-40": "var(--color-yellow-500-opacity-40)",
      },
      button-primary-default: "var(--color-button-primary-default)",
    },
    backgroundColors: {
      primary: "#ffffff",
    },
  },
};
```

### `tailwind.config.js` Data Flow

1. Build `collectionById` from all local variable collections.
2. Build `fontFamily.sans` with `getTailwind3FontFamilySans()`.
3. Filter all local variables to color variables:

```ts
variable.resolvedType === "COLOR"
```

4. Sort color variables by collection name and variable name.
5. For each color variable:
   - Find the variable's collection.
   - Select `Light` mode when present.
   - Fall back to the collection default mode.
   - Generate a CSS variable name from the Figma variable name:

```ts
const cssName = toCssCustomPropertyName(variable.name);
```

6. Convert that CSS name into a Tailwind config value:

```ts
const cssVariableValue = `var(${cssName})`;
```

7. Decide if the variable belongs in background colors:

```ts
getBackgroundColorKey(variable.name)
```

8. If it is a background token, add it to `theme.backgroundColors`.
9. Otherwise, add it to `theme.colors`.

### Tailwind 3 Color Key Rules

Semantic duplicate prefixes are collapsed before export:

```text
button-button-*   -> button-*
icon-icon-*       -> icon-*
divider-divider-* -> divider-*
control-control-* -> control-*
link-link-*       -> link-*
logo-logo-*       -> logo-*
text-text-*       -> text-*
input-input-*     -> input-*
```

This is handled by:

```ts
normalizeRepeatedTailwindColorPrefix()
```

Primitive palette colors are grouped under color objects:

```text
--color-blue-*    -> colors.blue
--color-red-*     -> colors.red
--color-grey-*    -> colors.grey
--color-pink-*    -> colors.pink
--color-yellow-*  -> colors.yellow
--color-crimson-* -> colors.crimson
```

This is handled by:

```ts
getTailwindColorKeyFromCssName()
setTailwindColorValue()
```

Example:

```text
--color-yellow-100
```

becomes:

```js
yellow: {
  100: "var(--color-yellow-100)",
}
```

Opacity shade keys stay quoted:

```js
yellow: {
  "500-opacity-40": "var(--color-yellow-500-opacity-40)",
}
```

Pure numeric shade keys are unquoted:

```js
yellow: {
  100: "var(--color-yellow-100)",
}
```

This formatting is handled by:

```ts
toJsObjectLiteral()
```

### Tailwind 3 Font Family Rules

`theme.fontFamily.sans` is generated from typography variables that produce CSS custom property names starting with:

```text
--family-*
```

This is handled by:

```ts
isFontFamilyCssName()
getTailwind3FontFamilySans()
```

The generated array includes every matching family CSS variable, then appends fallbacks:

```js
fontFamily: {
  sans: [
    "var(--family-noto-sans-sc)",
    "Arial",
    "sans-serif",
  ],
}
```

Variables that produce `--font-*` are not used for `fontFamily.sans`.

### Output: `index.css`

`index.css` is generated by:

```ts
buildTailwind3IndexCss(collections, variables, variablesById)
```

Current output shape:

```css
/* Generated 2026-07-29T... */

:root {
    --color-yellow-100: #fff3a3;
    --family-noto-sans-sc: "Noto Sans SC";
}
```

Earlier output included:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  :root {}
}
```

The requested iteration removed the Tailwind directives and removed the `@layer base` wrapper. The file now outputs only a top-level `:root` block.

### `index.css` Data Flow

1. Build `collectionById`.
2. Prefer primitive color variables from primitive color collections.
3. If no primitive color variables are found, fall back to variables from the color collection.
4. For each selected color variable:
   - Read the collection default mode value.
   - Convert the value with `makeColorCssValue()`.
   - Generate a CSS variable name with `toCssCustomPropertyName()`.
   - Add a declaration to `:root`.
5. Add primitive spacing, border, size, and typography variables:
   - `--spacing-*`
   - `--border-*`
   - `--size-*`
   - `--family-*`
   - `--font-*`
   - `--font-weight-*`
   - `--line-height-*`
   - `--letter-spacing-*`
6. Emit all declarations inside a top-level `:root` block.

### Tailwind 3 Download Flow

The generated payload is sent to the UI with:

```ts
figma.ui.postMessage({
  type: "variables-json",
  data,
});
```

The UI stores:

```js
currentIndexCss = data.indexCss || "";
currentTailwindConfig = data.tailwind3Config || "";
```

The download buttons create files with `Blob`, `URL.createObjectURL()`, and an `<a download>` click:

- `Download index.css`
- `Download tailwind.config.js`

## Acceptance Notes

The current Tailwind 3 iteration supports:

- Top-level `module.exports`.
- Top-level `content`.
- Top-level `darkmode: "class"`.
- `theme.fontFamily.sans` from `--family-*`.
- `theme.colors` with nested primitive palettes.
- `theme.backgroundColors`.
- Top-level `:root` output for `index.css`.

The current Tailwind 4 iteration supports:

- `@theme` base token output.
- `@theme` color token output.
- `@utility` typography output from Figma Text Styles.

The main known follow-up is aligning Tailwind 4 color export with the Tailwind 3 all-color-variable scan.
